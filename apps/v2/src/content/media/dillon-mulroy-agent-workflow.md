Dillon Mulroy keeps the driver seat while using AI. The point is not to hand over the whole job. It is to keep enough shape and pressure on the work that the tool stays useful.

## Notes

- [38:37](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=2317s) - Pi keeps the setup small. A short system prompt keeps the model on task. Related: [Pi](https://pi.dev/).
- [40:00](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=2400s) - Stable tools matter. A setup that does not shift all the time gives steadier results. Related: [Dillon's skills repo](https://github.com/dmmulroy/skills), [Dillon's dotfiles](https://github.com/dmmulroy/.dotfiles/tree/main/home).
- [44:10](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=2650s) - Herdr gives him a place to juggle sessions and terminal tabs. It fits the rest of his setup because the shell stays close at hand and the work stays visible.
- [46:38](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=2798s) - Plannotator moves review out of chat and into a view that can be marked up. This is the best part of the talk to me, I think this is what I've been looking for! Links: [Plannotator](https://github.com/backnotprop/plannotator), [LMV](https://github.com/backnotprop/lmv).
- [48:30](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=2910s) - `/tree` in Pi gives room to try a branch of work and come back without losing the main line. Related: [Pi docs for sessions](https://pi.dev/docs/latest#sessions-as-trees).
- [54:18](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=3258s) - Types and interfaces come first, so the rest of the work has a clear shape.
- [57:00](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=3420s) - Before he trusts a change, he wants the command line to show that it works.
- [1:08:14](https://www.youtube.com/watch?v=-DKSg1-v1Gg&t=4094s) - Wayfinder looks like a fit for bigger work, where a clear path matters before the work starts. Related: [Wayfinder](https://github.com/mattpocock/skills/tree/main/skills/engineering/wayfinder).

## Takeaway

This talk links well with the "design at the interface" idea from [Should You Read the Code?](http://localhost:1414/should-you-read-the-code/). The shape of the work stays in human hands, while AI fills in the rest.
