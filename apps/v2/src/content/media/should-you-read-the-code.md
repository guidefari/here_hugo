The Primeagen breaks the "read the code" debate into three cases instead of one yes-or-no answer.

## Notes

- [03:15](https://www.youtube.com/watch?v=k13q6ecZLrw&t=195s) - For MVP work, internal tools, and quick trials, he does not care about the code path if the result feels right. AI agents can build the thing, and he is fine throwing it away if the idea proves worth keeping.
- [05:40](https://www.youtube.com/watch?v=k13q6ecZLrw&t=340s) - For work he cares about most, like a videogame he's writing, he wants full control and reads every line. He treats that level of care as part of the job.
- [07:51](https://www.youtube.com/watch?v=k13q6ecZLrw&t=471s) - His middle path is to design the API, the interface, and the join points by hand, then let AI fill in the bulk of the code. He keeps control of the shape of the system while moving fast on the rest. Related: [Dillon Mulroy also speaks about type driven development.](http://localhost:1414/dillon-mulroy-agent-workflow/).
