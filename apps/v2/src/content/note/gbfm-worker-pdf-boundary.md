The [Bun version](/gbfm-bun-pdf-generation) loaded custom fonts from its filesystem. The Cloudflare migration removed that runtime need, and the API Worker now asks `pdf-lib` for a built-in font.

```ts
import { PDFDocument, rgb, StandardFonts } from 'pdf-lib'

const fontBold = yield* Effect.tryPromise({
  try: () => pdfDoc.embedFont(StandardFonts.HelveticaBold),
  catch: (error) =>
    new DatabaseError({
      message: `Failed to embed font: ${getErrorMessage(error)}`,
      operation: 'font',
      table: 'pdf'
    })
})
```

QR images also stay in memory. The service decodes the data URL with Worker APIs before embedding the PNG.

```ts
const binaryString = atob(base64Data)
const bytes = new Uint8Array(binaryString.length)
for (let i = 0; i < binaryString.length; i++) {
  bytes[i] = binaryString.charCodeAt(i)
}
return pdfDoc.embedPng(bytes)
```

`pdfDoc.save()` returns bytes. `S3Service` keeps its old name while its Worker layer writes through a native R2 binding.

```ts
const pdfBytes = yield* generateQROnlyPdf(mix, qrDataUrl)

yield* s3Service
  .uploadFile(cacheKey, Buffer.from(pdfBytes), 'application/pdf', bucketName)
```

The public URL comes from the CDN router, which reads the stored object through an R2 binding.

```ts
const url = `${cdnUrl}/user-content/${cacheKey}`
return { url, cached: false }
```

## Take aways

- Workers can run this PDF code once the generator stops reading local files.
- Built-in fonts shrink the runtime boundary and change the typography.
- The API Worker hands generated bytes to object storage.
- A separate CDN Worker can serve the file without running the generator.

Commit `986813f07` removed `node:fs`, `node:path`, `fontkit`, and the local font reads. The current snippets live in `apps/server/src/services/qrcode.service.ts`.
